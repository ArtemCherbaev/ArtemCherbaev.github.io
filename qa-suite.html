Run the QA suites

The agentic Playwright suite is public and runs on any machine with Node and Docker. Below is how to run it yourself, and what each published report answers.

Run it locally

Four commands from a clean checkout. The visual suite runs in the same image CI uses, because baselines are Chromium on Linux and a local Windows or macOS run would compare against a set that was never committed.

  1. Clone and install

    Yarn 4 is pinned through Corepack, so there is nothing to install globally. 

    $ git clone https://github.com/artemcherbaev/agentic-playwright-suite.git
$ cd agentic-playwright-suite
$ corepack enable
$ yarn install

  2. Install the browser

    Only Chromium is needed for the functional suite locally; CI adds WebKit. 

    $ yarn playwright:install:chromium

  3. Run the functional suite

    Twenty end to end cases against the demo storefront. Add a grep while working on one case. 

    $ yarn test:e2e
$ yarn playwright test --grep "TC-12"

  4. Run the visual suite in the CI image

    Twenty screenshot comparisons against committed Linux baselines. 

    $ yarn docker:vr

Published on every push to main

Each report answers a different question, which is why there is more than one. All of them are regenerated by the pipeline, never by hand.

Report What it answers
Suite health Pass rate, flaky rate, p50 and p95 duration, repeat offenders, each against a stated threshold rather than a vibe.
Test results Both suites in one dashboard, with the Chromium and WebKit runs split under the functional one.
Functional The end to end suite on its own, with its trend across runs.
Visual The screenshot suite on its own, with expected, actual and diff for any failure.
Trace viewer Every step of every case, replayable, including the network and the DOM at each step.

What the pipeline does

Trigger Runs
Pull request Static checks, functional suite, visual suite.
Push to main The same, then the dashboards and the suite health page publish.
Image or lockfile change The execution image is rebuilt and pushed to the registry first.

Main is protected and takes no direct pushes. Every change arrives through a pull request, and the only required check is a gate job that reads the result of all the others, so a job that stops running cannot quietly stop being enforced.
